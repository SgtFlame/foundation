Built 2026-11-27 ([Calendar.md](Calendar.md) › *Built in forge 28f*). The `calendar` library app gained `calendar.connect` (a tool making connected calendars), the jobs `calendar-pull` (an incremental `event.list` from the stored cursor, a full one when the cursor expired, every item mirrored by the command `calendar.event.mirror`, which picks its target by `outsideId`, then by our `iCalUID`) and `calendar-push` (creates keyed by the record id, updates with the etag, a conflict kept in `refusedChange` and a pull), and the triggers `onConnected`, `onOutsideChanged`, `onOutsideRemoved`, `onCatchUp` (daily) and `onEventEdited` (only on people's changes, so the app's own mirrored writes never echo back; `onEventChanged` takes `ownChanges` so mirrored events get occurrences). Later parts: a real calendar type only implements `calendar.events@1` and passes `calendar/contracttest`; every job id is derived from the record and its sequence, so two runners never double a write (Forge's `TestTwoProcesses`).
