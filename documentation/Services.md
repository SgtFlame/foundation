# Services over NATS

Every service is a Go interface (`<s>service.Service`) with a real implementation (`impl`). Forge's iteration 21 (`../../forge/documentation/plans/021-ProxyServerServices.md`) lets any service run in any process: a **proxy** implements the interface by sending each call over NATS, and a **server** receives it and calls the real implementation. Callers cannot tell a proxy from the real one. The code is `backend/features/services`.

## Built in forge 21a-1: the wire

- **Subjects**: a call is a NATS request on `svc.<service>.<Op>` (`svc.usage.Summary`), `<service>` being the service package's name without `service`. Servers subscribe to `svc.<service>.>` in the queue group `svc.<service>`, so several processes share the work with no leader, and read the operation from the subject's last token (`services.OpOf`), which leaves room for a routing suffix.
- **Body**: the `<Op>Args` as JSON with the embedded `features.ServiceArgs` zeroed (`services.Encode`); the response likewise, with `Common.Trace` left out. Go field names travel as they are: the wire is Go to Go, not a DTO.
- **Headers** (`services.Headers`, the connector bus's split): `Svc-Call` (a TSID), `Svc-Trace`, `Svc-Deadline` (from the caller's context, else `DefaultTimeout`), `Svc-Meta`, `Svc-Idempotency`, `Svc-Tenant`, `Svc-Caller`, and `Svc-Principal`. **`Svc-Principal` is trusted only by a server built with `services.TrustHeaders()`** (tests and loopback); any other server answers a call carrying it with 401 `call_untrusted`, and a call without one runs as the anonymous principal.
- **Replies**: the operation's response; the server logs a failure once (as `args.Fail` already does) and the proxy rebuilds the same `ServiceResponse`. Failures of the call itself are responses too: no responders 503 `service_unavailable` ("The usage service is unavailable."), deadline 504 `service_timeout`, a reply that does not decode 502 `service_bad_reply`, a body that does not decode 400 `service_bad_request`, an unknown operation 501 `service_unknown_op`, a canceled caller 499 `call_canceled`.
- **Retries**: `services.Call(..., services.Idempotent())` (or `services.Key(k)`) sends again on no responders, backing off 100, 200, 400 ms within the deadline (`Client.Retries`, 3); other calls are never retried.
- **The pieces**: `services.Call[R](client, service, op, args, opts...)` is a proxy method's whole body; `services.Serve(nc, service, ops, opts...)` with `services.Unary(svc.Op)` per operation is a server's; `Server.Stop` leaves the queue group and waits for calls in flight; a server runs up to 256 calls at once (`services.Concurrency`).
- **Logs**: each call logs a `svc.call` record on both sides (`service`, `op`, `code`, `durationMs`, `side`), at debug, under the call's trace, so a call across processes reads as one trace.
- **The proof**: `usageservice/proxy` and `usageservice/server`, hand-written; `usageservice/impl`'s tests run against the real implementation and again through them.

## Built in forge 21a-2: the generator

- `cli gen services` (in Forge `forge gen services`; `gen.Command()` is shared) reads every `features/**/services/<s>service/Service.go` with `go/parser` and writes, beside it, `proxy/proxy.go` (`proxy.New(client)`, a `<s>service.Service`) and `server/server.go` (`server.Ops(svc)`, `server.Serve(nc, svc, opts...)`), and `features/services/catalog/catalog.go`: every service as a `services.Spec` (wire name, interface type, operations, `Proxy`, `Serve`), which the locator (21f-1) will use. Generated files start with `// Code generated by cli gen services. DO NOT EDIT.`.
- **Markers** on an operation's doc comment: `//svc:local` (only callable in the same process), `//svc:stream` (hands back a channel; generated as 501 `service_stream` until 21c), `//svc:idempotent` (retried on no responders), `//svc:job` (may run for minutes). A proxy's `Local` field, when set to a real implementation, runs local and streamed operations in this process; otherwise they answer 501 (`services.NotServed`: a response's `Common`, or a request whose response channel delivers the failure). An embedded interface (`configservice`'s `config.Reader`) becomes a field of the proxy that its caller sets.
- **Refusals**: the generator refuses an operation not shaped `Op(args <Op>Args) <Op>Response` unless it is local or streamed; `TestEveryOperationTravels` (`features/services/catalog`) walks every travelling operation's args and response by reflection and fails on a channel, a function or an interface with methods at any depth (`services.CannotTravel`). Marked local when this was built: `uiservice.Open|Event|Close`, `collabservice.Collaborate`, `liveservice.Serve` (they hold the browser's socket), `cognitionservice.NodeTypes` and `configservice.Sections` (registry reads every process can answer; their types hold functions), `recordservice.Upload|OpenFile` (readers, until the `files` service of 21d-4). Streamed: `chatservice.Stream`, `configservice.Watch`, `kbservice.OpenVolumeAsync`, `logsservice.Tail`, `conversationservice.Send`.
- **The check**: `go test ./features/services/gen` (and Forge's `go test ./features/services/...`) fails when anything generated is stale or missing, naming the file; `FOUNDATION_GEN_UPDATE=1` on the same test, or `cli gen services`, rewrites them. `cli gen services --check` is the check for scripts.

## Built in forge 21b: call identity

- **The call token** (`services.Token`, header `Svc-Token`): who a call is for, the principal as a `features.PrincipalRef` (with its reach, `MemoryOf` and, new, `Service`) and its tenant, issued and expiring (`TokenTTL`, 5 minutes), and `Parent` (the hash of the token it narrows). Signed with Ed25519 (`services.Keys`): a server needs only the public keys (`services.VerifyWith(keys.Public())`), so nothing that verifies can mint.
- **Who mints**: a process that runs an entry point (the web service, the job runner, triggers) holds the private key in its `services.Client.Keys`; when it sends a call whose context carries no token for the call's principal it mints one there, at the process boundary, rather than at each entry point's call site (the decision taken while building: every principal such a process acts for already passed its own entry checks). A process without the key (a data service) only **forwards** the token its call came with (`services.WithToken`, put in the context by the server, so `args.Context()` carries it on). Asking such a process to call for another principal is refused with 403 `call_principal_changed`; a process with the key narrows by minting a child whose `Parent` names the original (an agent's run under a person's call).
- **The server's check**: signature and expiry, then the principal rebuilt into `ServiceArgs` and the operation's own `authz.Check` as before. Missing key or forged signature 401 `call_untrusted`; expired 401 `call_expired` (a forwarded token is re-minted 30 s before it expires where the key is held). In one process with no proxy nothing is minted or checked.
- **Not travelling**: a check decided by a role (`authz.WithAs`, as `forge.preview` runs a draft) holds a function, so a call under it is refused with 403 `call_as_local` (`authz.HasAs`); such runs stay in one process.
- **Service principals**: `features.ServicePrincipalFor(tenant, service)` (`Principal.Service`, `String()` `service:<name>`) for background work that says which service acted.
- **Keys**: `<data-dir>/call.key` (`services.LoadOrCreateKeys`, JSON of the current private key and previous public keys; `services.ParseKeys` reads the same from Vault's `server/call-key`, 21h). `cli secrets rotate-call-key` makes a new key and keeps the old one's public key as previous, accepted until the next rotation.

## Built in forge 21c: streams and cancellation

- **Streams**: an operation marked `//svc:stream` (it returns an `<Op>Request` holding channels) is `services.Stream` in its proxy and `services.Streamed` in its server. The call goes to `svc.<service>.<Op>` with a reply inbox of the caller's own. The server sends a **head** (the request's fields that are not channels, such as `logsservice.TailRequest`'s `Common`, with an `Svc-Ack` header naming its ack subject), then frames `{f, seq, v}` for each value of each channel, `{f, closed}` when a channel ends, `{hb}` every `Heartbeat` (5 s) while idle, and `{done}` last. A channel whose values carry a `Common` (a response channel) ends after its first value; any other ends when the implementation closes it.
- **Flow control**: the server sends at most `Window` (64) values before the caller acks; the caller acks every 32 values it hands on, so a caller that stops reading holds the server back.
- **Lost streams**: a caller that hears nothing for `StreamIdle` (15 s) ends the stream, sending 503 `service_lost` on each response channel that has not ended and closing the rest. A stream that cannot start (no server, a refused head) fills the request the way `NotServed` does: its `Common`, its response channels holding the failure, and its other channels closed.
- **Cancellation**: when a caller's context ends, for a stream or a plain call (499 `call_canceled`), it publishes `svc.<service>.cancel.<callId>`. Every server of the service subscribes to these subjects outside its queue group, and the one holding the call cancels the call's context. Queue groups ignore `cancel` and `wait` subjects.
- **Waiting in one process**: `services.WaitSubject(service, keys…)` (`svc.<service>.wait.<key>…`, keys made tokens by `SubjectToken`) is where one process waits for a call about one thing. It is served with `ServeAt`, a plain subscription, and sent to with `CallAt`, with the same headers and token as `Call`. A chat round's paused tool call is the first user: with `conversationimpl.WithCalls(client, serverOpts…)`, each waiting call is also served on `svc.conversation.wait.answer.<roundId>.<callId>`, and `Answer` for a call not waiting in this process is sent there. No responders gives 404 `call_not_waiting`, and the owner is checked where the round waits.
- `tools.Tool`'s `Asks` and `Run` are `json:"-"`, so a chat's client tools travel as metadata in `conversation.Send`. `CannotTravel` now checks streamed operations too: their args, their request's fields, and each channel's values.

## Built in forge 21d-1: data services

See [DataServices.md](DataServices.md): the inventory of storage owners, the guard test, policies reading grants through `authzservice` in other processes, and records' user names through `userservice.Names`. A server now drops its reply when the caller has already given up (its deadline passed or it canceled), so a late reply never races the caller's own 504 or 499.
