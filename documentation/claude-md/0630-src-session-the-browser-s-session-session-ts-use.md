- `src/session/` - the browser's session (`session.ts`: `useSession()`, `session.load|started|logout|switchTenant|updated`; refreshes a minute before the access token expires and, through `setUnauthorizedHandler` in `http/client.ts`, once on a 401, then retries; identity requests pass `noRefresh`), `RequireSession` (guards `/workbench`, sends the browser to `/login?next=…`, starts log forwarding once there is a session) and `AccountMenu` (the foot of the side bar: tenant switcher, which reloads the page; *Account…*; *Sign out*; *Set up accounts…* in single-user mode). The clients are `Identity.ts`, `Tenants.ts` and `Users.ts`; the cookies are HTTP-only, so the browser never reads a token. `permissions.ts` mirrors `authz.Check` over `GET /authz/me` (`Authz.ts`; with scoped app-role permissions and fences): `useCan()` gives `can(action, resource?)` (the tenant when no resource is given) to hide or disable what the user may not do, `canIn(ctx, …)` reads it in a command's `when` (the Editors view passes `{ can, tenantId }`), and `permissions.load()` refreshes it after a grant changes; the server's check is authoritative. Read settings with `useConfig`/`useSetting`, which default to the user scope (what the server resolves for the user).
