- `src/editors/<name>/` - one directory per editor, holding the editor component (`<Name>Editor.tsx`), the object type it edits (`<Name>Object.ts`) and its `contributions.ts` (the `workbench.editor` contribution). `editors/tenants/points.ts` declares `tenants.action` (an action on the selected tenant in Administration › Tenants: `{title, confirm, run(tenant)}`, confirmed first; Forge's *Seed prefabs*). `editors/dashboard/points.ts` declares `dashboard.widget` (`{ title, size: 'full' | 'half', component }`, props `{ refresh, registry }`; `refresh` changes on focus and every minute); `dashboard/usage/` is the *Usage & cost* widget, whose chart colours come from `palette.ts` (a validated categorical order, light and dark steps, at most seven series plus a grey Other). `editors/chat/points.ts` declares `chat.contextSettings` (a control in the composer's ⚙, paired by id with a server `chat.contextProvider`; defaults are the server's `chat.context.defaults.<id>` section), `chat.command` (`/new`, `/level`, `/mode`, `/help`) and `chat.clientTool` (a tool the model calls in this browser: `{ title, description, input, effect: 'read' | 'ui', run?(args, { registry, store, tabId }), Card? }`; one with a `Card` waits for the user's answer in the transcript, the rest run as soon as their `tool` event arrives and `useChatStream` answers for them; a client tool never changes data, which is for server tools that ask).
