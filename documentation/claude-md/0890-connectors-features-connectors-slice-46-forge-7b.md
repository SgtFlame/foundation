**Connectors** (`features/connectors`, slice 46, Forge 7b, `documentation/Connectors.md` › *Built in slice 46*, which also holds the bus protocol): services outside the tenant described by metadata. A `connectors.Contract` (`id@version`, versions side by side) has operations (`args`/`result` object schemas, examples, `effect` read|write|send, `destructive`, `key`, `errors`, `callbacks`) and events (`payload`, `idFields`, `delivery` watch|callback, `subscription`); a `connectors.Type` implements one version of each contract it names (`settings`, `noConnection`, `discovers`, `receives`). **Every builtin contract and type must pass `connectors.CheckContract`/`CheckType`** (titles, descriptions for a model, tags, described fields, examples that pass, and the tool shape: `<contract>.<op>` ≤ 64 characters, object args and result, no `$ref`/top-level `oneOf`, ids without `_`); `apps/tools`' `TestMetadata` runs it, and the registry refuses announcements that fail it. `ToolSpec`, `MCPTool` (MCP `MCPRevision`), `FunctionSpec` (gemini, anthropic, openai) and `OpenAPI` map metadata to tools; their golden files are in `connectors/testdata/golden` (`go test ./features/connectors -update` after a deliberate change). Every call is NATS request/reply on `cx.call.<tenant>.<type>.<connection>.<op>` (ids as tokens, `.`→`_`), never a Go call, even in-process: `connectors.Dispatcher.Call(args, Call{Contract, Operation, Connection, Args})` resolves the type (a connection's through `Connections`, 7c; else one needing no connection), sends `Cx-*` headers and returns the result or a typed `*connectors.Error` (`auth|notFound|conflict|invalid|rateLimited|unavailable|notSupported`; its `Retryable()` is what `jobs.Classify` reads; *no responders* is `unavailable` at once). `adapter.Serve(ctx, nc, adapter.Options{Types, Contracts, Impls, Surfaces, Resolve, …})` is the adapter runtime, the same in-process (`serve.go`'s `connectorImpls()`, empty until 7e) and in an external binary: queue groups `cx.<type>`, one `Session` per tenant/type/connection dropped on `cx.changed`, announcements refreshed in KV `cx_adapters` with an `expiresAt` the registry checks. `connectors.Registry` merges builtins, announcements and discovered contracts (`cx_discovered_<tenant>`, `conn.<connection>`); read it with `useQuery('connectors.contracts'|'connectors.types'|'connectors.describe')` (types in `@foundation/common/services/Connectors.ts`). *Call connector*'s pins come from `Normalize` (one pin per top-level field; nested objects one `json` pin); a retryable error fails the run (a job retries) unless `catchRetryable`; `NodeType.SampleFor` stubs it with the example result in sandboxed runs. `cx.in.>` is reserved for iteration 75: never subscribe to it. Test with `go test ./features/connectors/...` (`connectorstest` holds the test contract and types: `test.echo`, `test.secure` and `test.exclusive`, whose sessions also `Watch` a scripted event source; an external adapter is the test binary run again; `natsd.StartTestListening`, `Server.Connect`). **Connections** (slice 47, Forge 7c, `documentation/Connectors.md` › *Built in slice 47*, `features/connectors/connections`): a connection is a definition on the `def` stream (`connection.create|update|rename|disable|enable|delete`, internal `connection.setStatus`; projection `connectors.connection`, keyed `connection.<id>`), read by `connections.list {type?, contract?}` and `connections.describe {id}` (secrets only `{set}`), tested by the `connection.test` call and tool (the type's `check` operation; give every connection type a contract with one). **Secrets never enter a command's stored args**: `live.Command.Seal` (run by the bus, `Transact` and dry runs after the authz and argument checks) puts each value in the `config.SecretStore` under a new version and leaves `{"$ref": <version>}` (placeholders in KV `cx_secrets_<tenant>`); `live.Command.NoTool` keeps such a command out of the command tools; the browser sends it with `live.command(…, {secret: true})`, which DevTools records as `•••`. Access: resource type `connection` (`read`, `use`, `manage`; Owned, fenced by `user`; a user's own connection is used and managed by them alone, `connections.CheckAccess`). The dispatcher's `Connections` (`connections.Connections`) checks `use` and the status before each call; `Dispatcher.Failed` commits `error` on an `auth` reply; keyed operations go through the ledger (`cx_ledger_<tenant>`, written by `adapter.Context.Accepted` or the runtime); `Type.Exclusive` types run each call under a lock in `cx_locks_<tenant>`. Foundation answers adapters on `cx.resolve` and `cx.status` in the queue group `cx.foundation` (`connections.Serve`); adapters resolve over the bus unless given `Options.Resolve`. **Event sources**: every process keeps KV `cx_sources` (`<tenant>.<connection>`, `connections.Start`/`Reconcile` from installs with *On connector event* and connections); adapter instances lease them in `cx_leases` (share plus one), run `Watch`, publish to `CX_<tenant>` with the event id as `Nats-Msg-Id` and then store the cursor in `cx_cursors`; *On connector event* is a `livenodes.TriggerEvent` with its own `Stream` and an `Accept` hook (`connections.ContributeTrigger`); `connectors.sources` feeds the Jobs view's *Event sources*. The `connection` field type holds a connection id (optional `contract`); app exports leave its values out. The `connection.form` primitive is the generic form (Forge's *Connection form* prefab wraps it). Test with `go test ./features/connectors/connections` (each simulated process its own NATS connection; `connectors.LeaseTTL` shortened in `init`). **Scripted connectors** (slice 48, Forge 7d, `documentation/Connectors.md` › *Built in slice 48*, `features/connectors/scripted`): an app's manifest `connectors` (`apps.Connector {name, title, description, contracts, settings, operations: {op: graph}, watch}`, keyed list `app.addConnector|updateConnector|removeConnector`) implement contracts defined in Go (`apps.BuiltinContracts(reg)`, given to `apps.Env.Contract`/`DocumentEnv.Contract`) with the app's own `connector.op` graphs (*Operation called* `connector.operation`, *Return*, *Return error* `connector.returnError`), pinned into the version (`Manifest.ConnectorGraphs`, `Version.ConnectorGraph`/`WatchGraph`); installed, the type is `<appId>.<name>`, source `scripted`. `scripted.Serve` (every process, `serve.go`) runs one `adapter.Serve` per tenant over its installed scripted types, restarted new-first when they change: the types reach the registry by its **announcements**, and each call runs the pinned graph **as the app's principal** (the caller an output). *Emit connector event* (`connector.emit`) raises a contract's event on a connection of the app's own scripted type, published by `connectors.PublishEvent` with `connectors.EventID` (the code builtin `Watch`es use). Uninstalling, or an upgrade dropping a connector, disables its connections. A new node allowed in `server.action` that a connector operation may use should list `livenodes.KindConnectorOp` too. **Groups, validators and refs** (slice 49, Forge 7f, `documentation/Connectors.md` › *Built in slice 49*): `Type.Group` puts a type's tenant connections under `tenant:<t>/connectors:<group>` (`connections.Resource(tenant, owner, group, id)`, `Parent`), where a role scoped there reaches them and no others (Forge's *Mail administrator*, a contributed role, granted beside a member's role); `connections.Validators` (`connection.validator`) check a connection's settings beyond its schema in `connection.create`/`update`; a settings field with Configuration's `ref` (`<section>#<arrayPath>`) reaches the adapter as the item it names, resolved on `cx.resolve` (`connections.Deps.Config`, `Extensions`; `RefItem`), so adapters never read configuration. **Slice 50** (Forge 7i, `documentation/Connectors.md` › *Built in slice 50*): *Connections of type* (`connector.connections`) lists the connections of the running app's own scripted types (settings, no secrets), *Wait* (`flow.wait`, at most 5 minutes, ends with the run) pauses a run, and *On record changed* takes `ownChanges` to start on its own app's changes too (`livenodes.TriggerEvent.Own`); its `record` is now read after settling the records projection, so it holds the change.
