Documentation and plans: `documentation/` documents what is built, one file per feature (`documentation/Index.md` is a table of them, and `documentation/BuildHistory.md` records the dependencies, the seams and each slice). `documentation/plans/` holds what remains, one file per feature with the same name: the design still to build and a `## TODO` section (open questions with *Decision* lines, what to review after seeing it ★, what is not built yet); `documentation/plans/Index.md` is a table of them with the remaining work in brief, and `documentation/plans/Backlog.md` holds ideas no plan owns yet. When something is built, its description moves from the plan into the feature's document and leaves the plan's TODO. `CLAUDE.md`, `documentation/BuildHistory.md`, `documentation/Index.md`, `documentation/plans/Index.md` and `documentation/plans/Backlog.md` are generated from fragment files (`documentation/claude-md/`, `build-history/`, `index/`, `plans/index/`, `plans/backlog/`) by `scripts/docs-index.sh`: never edit them by hand, add or change your own `NNNN-<slug>.md` fragment ([documentation/Fragments.md](documentation/Fragments.md); the user, 2026-11-27). Planned, not built: see `documentation/plans/Index.md`. Notable gaps: MCP and the Nexus tools, OIDC and per-tenant Volumes, Cognition's Prompt Editor, debugging and Replay, and the Nexus, `workbench.subjectDescriber` and `editor.getSelection`, saved Explorer queries and `Stats` charts. In the UI, memory entries are called *Chronicles* and knowledge base volumes *Volumes*.
