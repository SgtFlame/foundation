`chronicle` (`features/chronicle`, see `documentation/Chronicle.md` › *Built in slice 6*) is Chronicle memory. Tables `Entry` (tenanted and owned; `Type` is a built-in `chronicle.Types` ID, `ParentID` makes the tree, `Status` `active` or `proposed`, `Review` flags it), `EntryLink` (`related`, no direction) and `EntryRound` (`created`/`updated`, with the `Previous` summaries). `chronicleservice` (`/chronicle`: `POST list|get|create|update|delete|link|reindex`, `GET types`) edits them and keeps active entries in LanceDB's `entries` table (`chronicle/store/entrystore`, owner-filtered; unembedded entries are found by keywords, and `Reindex` runs at start and when the provider settings change). The pipeline is seam 3's step functions in `chronicle/steps`: `Candidates` (checked entries and their parents, the `chronicle` source's ranking, the window's last round's pinned entries, one hop of links), `Match` (stage 1 at the `ai.chat.stages` `match` level, JSON-schema output; falls back to the candidates' order) and `Update` (the memory update at the `memory` level: rewrites the used entries' summaries, proposes up to 3 entries). The `chronicle` context provider runs the first two and returns the chosen entries as pinned items with a `Reason`; the `chronicle` round follower runs `Update` and, on 🚫, flags what the round changed. A round's checked entries are its workspace's (forge 16c: `Send` puts them in the `chronicle` settings' `checked`, replacing the conversation's), and its active entries are its last round's pinned `chronicle` segments. **Sharing** (`MultiTenant.md` › *Built in slice 11*): `POST /chronicle/share {id, target}` shares with the tenant at once (`Entry.Shared = "tenant"`, a `shared` column in the entries table) or asks to share globally (a `ChronicleShare` snapshot, approved by a tenant moderator and then by a different global moderator through `POST /chronicle/shares {queue}` and `/chronicle/moderate`, which copies the entry into the global tenant); `target: ""` stops both. Reads use `chronicle.Visible` (own, the tenant's shared, the global tenant's but one's own copies) and the `chronicle` source also searches the global tenant's table; writes and the memory update use only `chronicle.Owned`, so nobody changes another's entry.
