**Jobs** (`features/jobs`, slice 45, Forge 7a, `documentation/Jobs.md` › *Built in slice 45*): durable background work. A job (`jobs.Request`: id = idempotency key, graph, event, trigger, inputs, `as` a `features.PrincipalRef`, app, queue, key, runAt) runs a published graph once, as the principal it names, retried with backoff while it fails retryably (`jobs.Classify`: a `*jobs.Failure` from *Fail* `{retryable, after}`, or any error with `Retryable() bool`), then dead. Its state is CQRS: `job.enqueue|start|finish` (internal) and `job.cancel|retry` (tools) on area `jobs`, folded by `jobs.job`, read by the live `jobs.list {app?, status?, graph?}` and `jobs.trace {id, runId}` queries (Administration › Jobs, `frontend/common/src/editors/jobs/`). Dispatch is the work-queue stream `JOBS_<tenant>` with one shared durable consumer per queue; delays and *On schedule* are JetStream message schedules (`@at`, `@every`, cron with a time zone); a keyed job runs only when it is the earliest message on its key's subject. `jobs.Runner` (`New`, `Serve(tenant)`, `Start(tenants)`, `Enqueue`, `Cancel`, `Outbox`, `Close`) is one process's share; `serve.go` makes one and serves every tenant. An installed app's manifest triggers (`apps.Trigger.Graph`, the app's own `app.trigger` graph) run as **the app's principal** (`features.AppPrincipal`, kind `app`, holding only its app's roles via `authz.AppGrants`; its events' actor is `app:<appId>`), from durable consumers on the event streams (`trg_<app>_<trigger>`) or message schedules, reconciled by every runner from `apps.install`; an event node that starts triggers registers a `livenodes.TriggerEvent` (`live.triggerEvent`: its subjects and outputs; `live.onEvent`, `records.onChanged`). A command graph's *Enqueue job* adds to `live.Decision.Enqueue`, carried on the commit's first event (`live.Event.Jobs`) and enqueued by the area's outbox follower (`project.FollowNew`), so it is enqueued if and only if the command commits; `NodeType.PureIn` lets that effect node into the pure command kind. Nodes (`features/jobs/nodes`): *Enqueue job*, *Cancel job*, *Fail*, *Job info*. Settings: the `jobs` section. Test with `go test ./features/jobs`, each simulated process its own `project.Projections`, bus and runner over one JetStream. **Generic graphs** (slice 54, for library apps such as Forge's Agents app): *Get record* and *Share* take an `entity` input, *Tools* an `include` input (an empty list joined selects nothing), *Call graph* `catch` (a *Failed* exit), *Call tool* (`tools.call`) calls a server tool by name as the run's principal, the Agent node takes `level` and gives each call's `args`/`result` and `usage`, and *Run in sandbox* (`apps.sandbox`) runs `sandbox.run` from a handler. *New id* makes a new id each time it is read: keep one in a graph variable (*Set variable*) when several nodes need the same id.
