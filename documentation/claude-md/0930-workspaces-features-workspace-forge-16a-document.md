**Workspaces** (`features/workspace`, forge 16a, `documentation/Workspaces.md`): a person's workspaces on the live core's own area `ws`, target type `ws_<userId>` from the principal (`live.Command.TypeFor`, so no command reaches another person's), *Default* (id `default`) made by the first read of `workspace.list`; `workspace.create|rename|move|delete` (tools) and `workspace.update {version, layout?, context?}` (`stale_workspace`, for 16b/16c); not ops, not activity. In the browser `src/workspace/`: `useWorkspace()` (`{workspaces, current}`, the tab's own id in `sessionStorage`, the browser's last in `localStorage`, Default when deleted elsewhere) is what every per-workspace part follows; the Workspaces menu above the account button, `/workspace`, the `workspace.switch` client tool; the workbench snapshot carries the workspace id and the `workbench` provider reads its name on the server. Since forge 16c each workspace holds its **active knowledge** (`context` `{kind: {id: checked}}`, only differences from the defaults: Volumes checked, entries unchecked; `workspace.Context`, `bad_context`): `conversation.send {workspace}` (empty is the caller's Default, someone else's id `workspace_not_found`) is read on the server through `conversationimpl.WithWorkspaces(workspace.KnowledgeReader(...))`, and the browser edits it with `useActiveKnowledge()` (`workspace/contextStore.ts`, a `ContextWriter` per workspace that re-applies its toggles on `stale_workspace`) in the Context side view and the Volumes editor. Since forge 16b each workspace holds its open editors and layout (`layout` `{format: 1, layout}`), saved by the workbench and replaced on a switch; which windows show a workspace is presence in `ws_<userId>.<id>` (private by `presence.Owned("ws")`), and a window opening a workspace another shows asks *Live follow* or *Don't save this window* (`workspace/windows.ts`). Since forge 16d each workspace has its **chats**: `Conversation.WorkspaceID` (where its first message was sent from) and `ConversationWorkspace` rows (*Show in…*); `conversation/list {workspace}` lists one workspace's (empty is Default, someone else's `workspace_not_found`), `POST /conversation/workspaces {conversationId, move?, shownIn?}` moves or shows one; whether a workspace exists is read on every call (`conversationimpl.WithWorkspaceList(workspace.IDLister(...))`, `conversation.OwnWorkspace`), so a deleted workspace's chats are Default's at once, and Default's list writes that down; `useChatStream(workspace, ready)` reloads on a switch. **Recent activity** (`features/activity`, forge 15c, `documentation/Activity.md`): what a person does by hand, in a per-tenant stream `ACT_<tenant>` with a subject per person (`act.<tenant>.<userId>`), each entry with a TTL of the `activity` section's `keepHours` and trimmed to `keepCount`, written idempotently by `Nats-Msg-Id`. The recorder (`activity.Recorder`) is the UI sessions' `ui.Recorder` (`ui` entries: handler, key path, visible label, never the payload) and the followers `activity.rec`/`activity.def` (`command` entries with changed fields by name, values only for short scalar types; `op` entries); `activity.focus` (a call the workbench sends for the focused subject), `activity.dismiss` and `activity.clear` are calls, never tools; `useQuery<Activity>('activity.mine', {after?, limit?, sendable?})` reads only the caller's own and refuses any principal parameter. Only users' gestures are recorded: never an agent's, an app's, a service's or the chat's (actor `chat`). A handler's commands share its event's request (`ui.CommandRequest` carries it with the page's app), and every event carries `command` and `app`. Never give a person's activity a tool, a principal parameter or an administrator's view; never copy content (long text, Markdown, rich text, files) into it.
