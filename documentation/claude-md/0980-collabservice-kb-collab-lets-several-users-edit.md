`collabservice` (`/kb/collab`) lets several users edit one volume file. `OpenFile` (`POST /kb/collab/files/open`) returns the file's room ID, the same for everyone; a room is a channel on the live connection (`collab.join {channel, fileId}`, then binary frames prefixed with the channel; `collab.leave`; `collab.closed {channel, code}`; `collabhandlers.ContributeLive`, which also checks the default tenant) speaking the y-websocket protocol (sync 0, awareness 1) plus our control messages (100, JSON: `role`, `seeded`, `ready`, `save`, `saved`, `compact`, and `edit`/`edited`, by which `EditFile` has the writer apply a tool's find/replace edits to the shared text (`collab/edits.ts`, the same rules as `collabservice.ApplyEdits`: each find exactly once); 101 compacted state). The server relays Yjs updates and keeps them as an opaque log; it never decodes the CRDT. The oldest connection is the **writer**: it seeds a fresh room from the file and autosaves (1s debounce); the server writes the file atomically via a dotted temp file. `OpenFile` and the WebSocket need `volume.read`; without `volume.write` the file is read-only (`readOnly` in `OpenFile`'s response, the editors open read-only): the room drops that connection's updates (except a writer's seed), ignores its saves, never sends it `edit`s, and a writable connection that joins takes the writer role. Empty rooms are dropped after 30s; joining a dropped room is closed with 4404 and the file must be opened again. Services share the volume path helpers in `volumeservice/Files.go`. The frontend side is `src/services/Collab.ts` and `src/services/collab/CollabProvider.ts` (`new CollabProvider(fileId, …)`, rejoining on a new channel when the connection comes back); room traffic is logged under the `collab` domain and shows as binary frames in DevTools' Live tab. **Documents of a kind** (slice 53, `documentation/MarkdownEditor.md` › *Changed in slice 53*): a `collabservice.DocumentKind` on the `collab.document` point opens a `collabservice.Document` (`Load`/`Save`/`Access` as the principal) that a room edits like a file, through `OpenDoc` (`POST /collab/docs/open`, every tenant; the default-tenant check is a file room's own); the records' `record` kind (`data.ContributeCollab`, `{entity, id, field}` of a `markdown` field) seeds from the field and saves with `record.update` as the writer. Saves run in order on the room's goroutine. A seed never marks a room dirty, and a writer handed a dirty room saves only once synced (saving earlier stored an empty document).
