`retrieval` (`features/retrieval`, see `documentation/ContextRetrieval.md` › *Built in slice 5*) is the context retrieval engine. A source with `Optional` (records) is searched only when a retrieval names it in `Sources` (RAG Search's switch). `features/retrieval/fuse` is the one weighted-RRF implementation (`fuse.Fuse`), also used by `indexservice.Find`. `retrievalservice.Retrieve` (`POST /retrieval/retrieve`) embeds the query once (`embed-query`; on failure it uses the keyword ranking alone and sets `VectorSkipped`), runs each `retrieval.source`'s vector and keyword search concurrently (a failing source is skipped), fuses per source with the Lexical↔Semantic dial (`w_vec = (a₁+5)/10`), multiplies by the Chronicle↔Library dial (`axisBase^(±a₂/5)`) and by grounding (`((1+up)/(1+down))^γ`, clamped, from `SegmentFeedback`, per tenant), then merges overlapping chunks of one file, keeps identical text once, and takes segments until Top-K or the budget (`min(budgetShare × window, maxBudgetTokens)`). A segment's `ID` is what fusion matches on, its `Key` what feedback counts against (a library chunk's content hash, so feedback survives reindexing while the text is unchanged). `retrieval.Vote` moves counts from a round's old verdict to its new one inside the caller's transaction. `indexservice.Match` carries the chunk `Hash`. The sources are `library` and `chronicle`; RAG Search searches both by default. **Tool searches take options from the call, never the model** (forge 15a, `ContextRetrieval.md` › *Changed in forge 15a*): `retrieval.WithOptions(ctx, retrieval.Options{Sources, LexicalSemantic, ChronicleLibrary, TopK, VolumeIDs})`, read by `kb.search` with `retrieval.OptionsFrom`; a chat round sets its RAG Search settings (`retrievalcontext.OptionsOf`), the Agent node its `retrieval` input (`retrieval.ParseOptions`); without options `kb.search` searches the Volumes alone as before. A model call's options come from its node's Retrieval group (forge 15b): `retrieval.Resolve(dials, presets, defaults)` (preset, then the node's dials, then `chat.context.defaults.rag`) and `Options.Narrow(pin)` (the run's Volumes; sources intersected, never widened), through `toolsnodes.RetrievalOf`. `retrieval.VoteOnce` (the `segment_votes` table) casts a vote once per key; the `retrieval.vote` tool and *Vote on segments* node (`features/retrieval/tools`) call it (action `retrieval.vote`, `Apps`), counting nothing in a sandbox or dry run. `kb.volumes` (`features/kb/live`) is the live list of Volumes the caller may read. **A chat round's workspace narrows every retrieval it makes** (forge 16c): `retrieval.WithScope(ctx, retrieval.Scope{ExceptVolumeIDs})`, read by `kb.search` and the `rag` gather and never replaced by options a model node sets; `ExceptVolumeIDs` runs down to `lancestore` as `volume_id NOT IN`. Test retrieval end to end with `retrieval/retrievaltest` (in-memory library and memory behind the real sources, `retrievalimpl.New`), never with a stand-in `kb.search`. **A searchable entity type may be a source of its own** (forge 18f, `ContextRetrieval.md` › *Changed in forge 18f*): `recordsource.Contribute` (over `data.SearchRecords`, so access and row rules decide) with a partition and a collection field (`Filter`/`RetrieveArgs`/`Options` `Partitions`, `Collections`, narrowed by `retrieval.Within`), and `recordsource.ContributeTool`; a source with `InChat` is searched by RAG Search, whose `sources` settings are now `RetrieveArgs.Switches` (a source left out is searched unless optional and not `InChat`).
