`cognition` (`features/cognition`, see `documentation/Cognition.md` › *Built in slice 7* and *Built in slice 14*) is the Cognition Engine. A `cognition.Graph` (nodes with typed pins, edges `{from: {node, pin}, to}`) is its own JSON document; a `NodeType` is a struct (`Title`, `Category`, `Event`, `Config` schema, `Pins` or `PinsFor(config)`, `Run(x *cognition.Exec, in cognition.Values) (Values, execPin, error)`), values pass as Go values and are read with `cognition.Get[T](in, pin)`. `cognition.Resolve` validates a graph. `cognition/engine` (`engine.New(db, registry, config)`, made in `serve.go`) runs one synchronously from an event (`Run(RunArgs{GraphID, Event, Inputs, Trigger})`): exec flow from the event node, pure nodes pulled once per run, Return nodes giving the outputs, limits from the `cognition` section, and every node's calls carrying `Meta.RunID`/`NodeID`. Each run is traced in `cognition_runs` and `cognition_run_steps` (values as JSON per pin, cut to a preview over `maxValueKB`, big integers as strings), written when it ends and purged unless among the graph's last `keepRuns` or younger than `keepDays`. `cognitionservice` (`/cognition`: `GET graphs|node-types`, `POST graph|runs|trace`) serves graphs, resolved pins, problems, runs and traces with usage per node. **Editing (slice 14)**: every node type needs a description, an example and described pins (`cognition.MetaProblems`; validation refuses others). A graph has a kind (what starts it, which nodes it allows, its `Spec`), an `owner`, a `spec` and `variables`; resolve it with `cognition.CatalogOf(reg).Resolve(g)` (kinds, conversions, metadata). Flow nodes run chains through `Exec.Flow(pin, frame)`; a loop's iteration is its own execution context, in which pure nodes are memoized; `Exec.Host` is what the run acts on (a UI handle, a command decision). Drafts (`cognition/drafts`) are aggregates on the `def` stream (target type `graph`), changed only by `bp.*` commands (`cognition.write`; `bp.publish {rev}` needs `cognition.publish` and refuses a draft that moved or has errors) and read through the `cognition.graph`/`cognition.graphs` queries; `bp.publish` commits a `published` event and the `cognition.published` projection is what `engine.Graph(args, id)` runs (`drafts.Source`), else the built-in. `RunArgs{Graph, Host, Trace, Limits}`: `TraceFailures` keeps only failed runs and counts the rest. *Call graph* takes `graphOverride` (forge 15b): a graph with at least the configured one's inputs and outputs run in its place, else `graph_signature`; `Exec.Start` runs a graph from any event with its own host (counted in the call depth), `Exec.Signature` reads a graph's signature, and `cognition.Scope` holds values a run shares with the graphs it calls. Chronicle's pipeline runs as the built-in **Personal** graph: the `chronicle` context provider runs its `event.userMessage` chain (Candidates → Match → Return items) and the round follower its `event.reply` chain (Branch → Update → Return changes), so a round makes two runs.
