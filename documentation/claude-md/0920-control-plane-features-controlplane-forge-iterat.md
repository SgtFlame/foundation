**Control Plane** (`features/controlplane`, forge iteration 20, `documentation/ControlPlane.md`): `controlplane/natsauth` is the deployment's NATS authorization as decentralized JWTs (operator; accounts `SYS`, `CTL` for `ctl.>`, `APP`; users with scoped permissions as creds files; the full resolver, accounts pushed with `natsauth.Push`), `cli nats init|user|replicas`; test against it with `natsauth.StartTestSecure(t)`. **Since forge 20a-3** each tenant's streams and buckets may live in its own account `T<id>` (`serve --nats-keys`, `cli nats tenant add`): code that names a tenant gets its JetStream from `Projections.JetStreamFor(ctx, tenant)` or `natsd.For` (a store with `SetAccounts`), never `Projections.JetStream()`, which is the services account the connectors keep using (`ControlPlane.md` › *Built in forge 20a-3*). Since forge 20a-4 a tenant's streams may be placed in a cluster of a supercluster by their names (`natsd.SetTenantPlacements`, `serve --nats-placements`, `cli nats place`): every per-tenant stream, bucket or object store name puts the tenant id first among its numbers (`natsd.TenantOfName`); test topologies with `natsd.StartTestSupercluster` and `StartTestSite`. Since forge 20b-1 the root tenant `features.RootTenantID` (3, *Infrastructure*, `serve --control-plane`, `cli controlplane init`) alone holds infrastructure: the `infra` resource type is pinned to it (`authz.ResourceType.Tenant`, reached only by grants in that tenant, not by the Super Administrator), with the roles 110 to 112 (`controlplane.ContributeAccess`). Since forge 20b-2 desired state is the root tenant's records of the `infrastructure` library app (`controlplane.SeedApp`), resolved by followers into the control account's `ctl_desired` per daemon target, with facts, heartbeats and the `CTL` stream of control requests' outcomes folded back into the records' reported fields (`controlplane.Control`, `controlplane.Start`); test above the daemons with `controlplanetest.FakeDaemon`. Since forge 20c-1 the daemon `axiomd` (`backend/cmd/axiomd`, no CGO: `scripts/build.sh -o out/axiomd`) enrolls with a one-time token (`cli controlplane enroll`, `ctl.ServeEnroll`) for creds scoped to its target, and runs `controlplane/daemon`; what daemons share with the control plane is `controlplane/ctl` (`ctl.Control`, formerly `controlplane.Control`), which must not import apps or records. Since forge 20c-2 `axiomd host` runs LXD instances from desired state (`controlplane/hostd` over the small socket client `controlplane/lxd`, each instance found by `user.axiom.id`); test it against the fake `lxd/lxdtest`. Since forge 20c-3 the only executable content a daemon accepts is a bash script named by its hash and signed by the root tenant's key (`infraScript` records, `ctl.PutScript`/`FetchScript`, the `script` verb). Since forge 20d-1 `axiomd agent` (`controlplane/agent`) installs and holds pinned packages (approved `infraAptSource`s only), renders unit files, runs systemd units and health checks; test it with the fake commands in `agent/testdata/bin`, never as root. Since forge 20h the credential issuer (`controlplane/issuer`) signs a placed `serve` unit's NATS user for a key its agent made and gets a wrapped single-use Vault SecretID for its set's AppRole, revoking both when desired state drops the unit; accounts are signed with the operator's signing key (`operator-signing.nk`). Since forge 20d-2 the agent runs `serve` units as `axiom-serve@<unit>` from a template, their credentials asked before each start by the oneshot `axiom-serve-creds@<unit>` (`axiomd unit-credentials`, the agent's root-only socket) and handed over with `LoadCredential=`; a unit is restarted within 3 days of its user's expiry, one per service set. Since forge 20e `infraNatsCluster` and `infraNatsAccount` records configure NATS: tenant accounts are signed and pushed with their limits (`controlplane.ApplyNatsAccounts`), and each nats unit runs as `axiom-nats@<unit>` with a rendered `nats-server.conf`, a change reloaded or restarted one node at a time under the cluster's lease in KV `ctl_nats_rollout`. Since forge 20f-1 first-party software is Debian packages (`scripts/package.sh`, `scripts/repo.sh`) in a signed apt repository published into the control account's object store `ctl_repo` (`cli controlplane repo publish`, `controlplane/packages`) and served by `axiomd repo-serve` on every NATS node's instance, every instance's desired state carrying it as the approved `first-party` source. Since forge 20f-2 `infraChannel` records follow the repository and a pin or unit naming a channel resolves per instance to the version its `infraRollout` reached: rollouts move in waves past a health gate, advanced by every process's sweep with expected-sequence updates (`controlplane.AdvanceRollouts`); test above the agents with `controlplanetest.FakeAgent`.
