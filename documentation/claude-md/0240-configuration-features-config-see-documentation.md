**Configuration** - `features/config` (see `documentation/Configuration.md` › *Built in slice 2*). A feature declares a `config.Section` (`Schema` and `Defaults` as raw JSON in the schema subset of `config/Schema.go`, optional `Check` and `Migrate`) and registers it from its `Contribute`; a section's value is always a JSON object, and paths are dotted with array items by index (`levels.0.modelRef`). Values resolve defaults → server → env → `app` → `tenant` → `user`, except that a flag or env value (`configimpl.WithEnv(section, path, value)`) wins over everything for `secret` fields. Services read settings with `config.Read[T](configService, args, sectionID)` (cached; secrets in plain text, Go only) and react to `config.Changes` (`config.Changed{Section, Scope}`). Never hand a secret to a client: `configservice` returns `{set, hint}` in its place (`{set}` with Vault). Secrets are kept through a `config.SecretStore` (`configimpl.WithSecrets`), which leaves a placeholder in the row: `config.CipherStore` seals them with AES-GCM in the row (`{"$secret": …}`, key `$FOUNDATION_SECRET_KEY` or `<data-dir>/secret.key`), and `vaultstore` (with `--vault-addr`) keeps them in Vault at `config/<scope>/<section>/<path>` (`{"$vault": {"version": n}}`); a save writes only the secrets it changed. `configimpl.WithServerSecret` adds the server's own secret from Vault's bootstrap bundle under every scope (source `server`). Plain settings need `config.write`; secrets need `secret.write` on `app` at the app scope (an *Application Administrator*) and `config.writeSecrets` elsewhere, and Settings lets a user edit only the fields they may write. REST: `GET /config/sections`, `POST /config/get|set|reset` (`set` takes a JSON merge patch and the view's `revision`: 409 `config_conflict` when stale, 400 `invalid_settings` with `errors: [{path, message}]`), and the live `config.changes` query (an upsert keyed by section per stored change). Requests name a scope kind (`app`, `tenant`, `user`), never IDs. A `config.SectionSource` gives sections per tenant (slice 33: an installed app's `app.<appId>`); `configservice` finds sections with `config.SectionsFor` for the principal's tenant and never caches a sourced one's value.
