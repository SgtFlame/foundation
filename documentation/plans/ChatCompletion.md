# Chat: the AgentOS Chat editor and the Markdown Editor's Chat tab

## Context
The backend has a provider-neutral `chatservice` (Gemini first) and a hybrid search index; see [AIChatEmbed.md](AIChatEmbed.md). This plan adds the two chat UIs that use them:
1. **AgentOS › Chat**: a chat editor for general conversations with long-term memory, through Chronicle ([Chronicle.md](Chronicle.md)).
2. **The Markdown Editor's Chat tab**: a fourth view beside Live Preview, Source and WYSIWYG, for asking about the open document. It is the first step toward editing the document with the AI.

Both are extensible through extension points ([Contributors.md](Contributors.md)):
- the composer's settings come from **ChatContextSettingsContributors**;
- levels, modes and defaults come from configuration ([Configuration.md](Configuration.md));
- every call's tokens and cost are recorded for the Dashboard ([Usage.md](Usage.md)).

Terminology: memory entries are **Chronicles**, and knowledge base collections are **Volumes**.

Status: planned. The `Chat`, `Embed` and `Index` clients exist; neither UI is built.

## Workbench layout
**Left side views** (`workbench.sideView`): vertical tabs down the left edge, replacing the hand-written `LeftMenuSidebar`.
- **Chronicles**: the memory tree (MUI `TreeView`), grouped by type and parent.
  - Each entry has a checkbox that makes it active for the focused conversation. The parent-inclusion rule applies: checking a child ticks its parents.
  - Each entry shows its title and slug, a dot when stage 1 updated it in the last round, a filter box, and a toggle to hide dormant entries.
  - Clicking an entry opens it in an entry editor tab.
  - The checkboxes follow the **focused chat tab**, because active entries are per conversation.
- **Volumes**: the existing volume browser, moved into a side view.

**Right border**: DevTools and **Settings** ([Configuration.md](Configuration.md)).

**AgentOS section**: opens **Chat** and **Dashboard** ([Usage.md](Usage.md)).

## Shared pieces
- **Client** `src/services/Chat.ts`: `complete`, and `stream(request, { onDelta, signal })` over SSE through `fetch`. The new `src/services/Chronicle.ts` streams `Send` the same way.
- **`src/components/chat/`**
  - **`ChatTranscript`**: a virtualized list of rounds. Assistant text renders with Live Preview's read-only markdown renderer, so code blocks and links match.
  - **`ChatComposer`**: a multi-line input. Enter sends and Shift+Enter adds a newline. `/` opens a command menu built from `chat.command` contributions (`/help`, `/new`, `/level deep`, …), and Stop aborts the stream.
  - **`LevelToggle`**: a segmented control with one button per entry in `ai.chat.levels` (by default Fast ⚡, Standard 💡, Deep 🧪). Hovering shows the model and an estimated cost for the current context size.
  - **`ChatSettingsPopover`** (⚙): renders every `chat.contextSettings` contribution, filtered by surface.
  - **`useChatStream`**: holds `rounds`, `pending` and `error`, and exposes `send(text)` and `stop()`.
- **Logging**: through `log.In('chat')`. Stream traffic does not appear in the Network tab (it uses fetch), so the clients log start, finish and failure.

## 1. AgentOS › Chat editor
**Editor** `src/editors/chat/`
- `ChatObject` has `kind: 'chat'` and `id: chat`. A single chat tab holds a continuous stream of conversations.
- `ChatEditor.tsx`: transcript, mode chips, composer.

**Transcript**: a continuous scroll of conversations.
- **"New conversation"** (the divider's ✕, or `/new`) starts a new `Conversation`. Its window and active entries start empty.
- Earlier conversations load lazily as the user scrolls up.
- A conversation's title is generated by a Fast-level call after its first round.

**Each round shows**
- **The user bubble**: editable. Editing regenerates the reply from that round, and later rounds are kept but marked stale.
- **The reply**: markdown, with **inline citations** `[n]` that are links. A citation to a volume chunk opens the Markdown editor at the chunk's line range, using the index anchors (`StartLine`, `Head`/`Tail` relocation). A citation to a Chronicle entry opens the entry.
- **A collapsible "Sources" row** listing the cited chunks with their snippets.
- **Chronicle chips**: the entries stage 1 used, each with ✕. Removing one records a correction (`RoundSegment`), and the next round excludes it.
- **Feedback**: 👍 Correct / 👎 Incorrect / 🚫 Ignore, neutral when none is set ([ContextRetrieval.md](ContextRetrieval.md)). 👍/👎 reweight the segments the round used. 🚫 greys the round out, because it leaves the window and the memory queue.
- **A "Context" inspector** (expandable): every injected segment with its source, rank, RRF score, axis multiplier and grounding multiplier, so the selection is never a black box.
- **A hover footer**: level, model, tokens in and out, cost, and latency, from that round's usage records.

**Mode chips**
- **Modes**: a mode is a published Cognition `mode` graph ([Cognition.md](Cognition.md)) plus a label and icon, listed in the `chat.modes` configuration. *Personal* is the built-in graph that runs the Chronicle pipeline. Agents built in the Cognition Editor can be chosen as modes too.
- The conversation's mode shows as a chip above the composer; clicking it switches mode, and ✕ returns to the default.

**Backend**: a new `chronicle` feature, as described in [Chronicle.md](Chronicle.md).
- **Services**: `chronicleservice` and `memoryservice`.
- **REST**: `chronicle/rest/...` handlers and DTOs, plus a `vite.config.ts` proxy for `/api/v1/chronicle`.
- **`Send{ConversationID, Text, Level, Mode, ContextSettings}`** runs this pipeline:
  1. the window;
  2. the enabled **context providers**;
  3. stage 1 context matching;
  4. stage 2, a streamed reply;
  5. a background memory update.
- **Streaming**: it uses SSE, as `/ai/chat/stream` does, with extra events:
  - `entries`, carrying stage 1's selection;
  - `sources`, carrying the citations;
  - `usage`, carrying tokens and cost when the round ends.

## ChatContextSettingsContributor
A contribution to the `chat.contextSettings` point:

```ts
{
  id: 'rag',
  title: 'RAG Search',
  icon: MenuBookIcon,
  order: 100,
  schema: { … },              // same schema language as configuration
  defaults: { enabled: true, lexicalSemantic: 0, chronicleLibrary: 0, topK: 8 },
  Control: RagControl,         // ({ value, onChange, disabledReason }) => ReactNode
  when: ctx => true,           // ctx.surface: 'chat' | 'document'
}
```

- **Values per conversation**: each conversation stores `contextSettings: Record<id, unknown>`, initialised from the defaults and sent with each `Send`.
- **Defaults are configuration**: the settings feature contributes a section `chat.context.defaults.<id>` for every contribution, using its `schema` and `defaults`. The Settings tab therefore edits each control's default with no extra code. This is where the two contributor kinds meet.
- **Backend counterpart**: a `chat.ContextProvider` registered with the same id.
  ```go
  type ContextProvider interface {
      ID() string
      Gather(ctx context.Context, req GatherRequest, settings json.RawMessage) ([]ContextItem, error)
  }
  ```
  - `ContextItem` is `{ Kind, Ref, Title, Text, Tokens, Score }`.
  - `Send` runs the enabled providers concurrently, then fills stage 2's context **budget** (part of the level's context window) by score. Items are cited by their `Ref`.
  - A contribution with no registered provider is hidden.
- **Built-in contributions**
  - **RAG Search**
    - On/off, with **preset chips** (*Code lookup*, *Brainstorm*, *Recall*, *Custom*) and two **11-step dual-axis sliders** from −5 to +5:
      - **Lexical ↔ Semantic** (BM25 vs vector RRF weights);
      - **Chronicles ↔ Library** (source multipliers).
    - **Top-K**.
    - **Temperature and Top-P overrides**, behind "Advanced". They default from the level.
    - Source toggles and a volume filter.
    - The algorithm is in [ContextRetrieval.md](ContextRetrieval.md). The backend counterpart is the retrieval engine, not a plain `Find`.
  - **Context**: whether the workbench snapshot (open editors, what each one is editing, recent subjects and selections) is sent with the message; see [WorkbenchContext.md](WorkbenchContext.md). In the document Chat tab it is forced on.
  - **Tools**: on/off, for tool calling. This needs tool support in `chatservice` first; see [Tools.md](Tools.md).

## 2. The Markdown Editor's Chat tab
- **Tab**: `MarkdownEditor.tsx`'s nested layout gains `{ name: 'Chat', component: 'chat' }`, lazy-loaded as `chat/ChatView.tsx`.
  - It reads the session's live `Y.Text`, so answers include unsaved edits and other users' edits.
  - It can be docked beside the document.
- **Components**: it uses the same `ChatTranscript`, `ChatComposer`, `LevelToggle` and `ChatSettingsPopover`. Contributions are filtered with `ctx.surface === 'document'`.
- **Context**
  - **Small documents**: the document is sent whole, with line numbers, up to about 200 KB.
  - **Larger documents**: its best chunks are sent instead, through `Index.find` with a new `Path` filter on `FindArgs`.
  - **System prompt**: it names the file and says to cite line ranges.
- **Navigation**: line citations (`L12–L18`) move the Live Preview or Source cursor to those lines.
- **Persistence**: the transcript is per session in v1. See Gaps.
- **Usage**: rounds are recorded with `Feature = 'doc-chat'` and the file id.

### Later: editing the document with the AI
- **Reply format**: the model returns structured edits through `JSONSchema`, as `{ explanation, edits: [{ find, replace }] }`. Anchoring on exact text survives concurrent edits better than offsets.
- **Applying edits**: they go to the shared `Y.Text` as a diff-match-patch patch, as `wysiwyg/yTextBridge.ts` does. They merge with collaborators' edits.
- **Review and undo**: proposed edits show as a diff to accept or reject, and each applied edit is one undo step.

## Verification (when built)
1. `yarn build` and `yarn lint` pass. Run `backend/scripts/serve.sh` and `yarn dev`.
2. **Chat**: open AgentOS › Chat.
   - Messages stream, and Stop aborts.
   - Citations open the cited file at the right lines.
   - The Chronicle chips match stage 1's selection, and removing one excludes that entry next round.
   - A 🚫 round no longer influences later turns. 👍/👎 change the grounding multipliers shown in the Context inspector on the next similar question.
   - Moving the Chronicles ↔ Library slider visibly shifts the cited sources.
3. **Levels**: switching Fast/Deep changes the model shown in the round footer, and the Dashboard's cost reflects it.
4. **Settings**:
   - Changing the RAG default in Settings changes the popover's initial value for new conversations.
   - Adding a level in `ai.chat.levels` adds a button to the toggle.
5. **Document chat**: open a note's **Chat** tab and ask about it. Edit the note, ask again, and the answer reflects the unsaved edit.
6. **No API key**: with Gemini's key missing, both UIs show the 503 message.
